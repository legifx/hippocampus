## 1. Method

where, and how it was verified. Every number was re-taken in this session on the reference

## 2. The findings, one by one

### 2.1 No CI (2nd §1.3, 3rd §4.3 / F04) — **closed**

`.github/workflows/ci.yml`. Two jobs on every push and pull request: `rust` (fmt check, clippy,
`cargo test --workspace --no-fail-fast` with the count taken by summing every `test result:`
line, on a checkout with full history so the hygiene gate can scan every patch) and `ui`
(`NODE_ENV=test npm test`, Playwright against the fixture). A third job, `latency`, runs only on
`workflow_dispatch` with an explicit flag, because a P95 from a shared runner under unknown load
is not a number this project accepts — it has a recorded case of three sessions optimising
something that was never slow.

Clippy warnings are reported, not fatal, for now: the workspace carried seventeen dead-code
warnings on the day the file was written, and a gate that is red on arrival is a gate that gets
ignored. The file says so and says when to flip it.

### 2.2 The Rust suite was red on a hygiene false positive (2nd §1.1, 3rd §4.1 / F05) — **closed**

`scripts/pre-commit`: the endpoint allow-list gained `debian.org` and the other documentation
hosts it was missing (`gnu.org`, `kernel.org`, `python.org`, `nodejs.org`, `spdx.org`,

Verified: `cargo test --workspace --no-fail-fast` → **1060 passed, 0 failed** (1054 before

### 2.4 Daemon anonymous memory 6× its budget with the CUDA runtime resident (all three) — **mechanism built; effect not yet measured**

`embedding.unload_after_idle_secs` (default 600). The ONNX session is wrapped in an
`IdleEmbedder` (`crates/cortexd/src/semantics.rs`) that the embedding stage asks to release
itself when the queue has been empty and no query has asked for an embedding for that long. The
two vector indexes stay — they are file-backed mappings and were never the problem. Two callers
get two behaviours, and the difference is the decision (D103):

- a **query** that arrives while the model is down is refused at once with a reason, the search
  runs its path and lexical arms exactly as on a machine that never fetched a model, and a reload
  starts in the background — so the price of the release is one keystroke answered by two arms
  instead of three, never a stall;
- the **embedding stage** blocks itself until the model is back before touching a batch.

Why a query must not wait: `cortex model reload` measured **1.58 s** wall clock on this machine.

The specification row for the memory budget now says what it measures: 250 MB anonymous *with
the model released or absent*. The resident session was measured at 1 305 MiB `RssAnon` during
this session (down from 1 646 in the evening before — it moves with what the runtime has cached).

**Not yet measured:** what `RssAnon` settles to after a release. That needs the new daemon
binary installed and running for ten idle minutes; the command and the pass condition are in
`03-PROGRESS.md`. If it settles below 250 MiB, D103 closed the finding; if not, the heap is the
owner and a second attribution pass is due.

Unit tests cover the release, the non-blocking refusal, the background reload and the single
reload under contention (`semantics::tests`).

**Addendum, first deployment the same night.** Two things the deployment found that the tests
had not. The release call sat in the branch the stage takes once, when the queue first empties,
and not in the settled short-circuit every later idle pass takes — so twenty idle minutes passed
without a release. Fixed. And the embedding stage was rebuilding the whole vector index every
five minutes (`expected=49257 present=49258`): a re-extracted file's deleted chunks left orphan
vectors that nothing removed, and the rebuild was the only path that caught up. Now the deleting
side notes the ids and the stage removes exactly those vectors (D107). One number from that run
is worth more than the mechanism: freshly restarted, with the model resident on CUDA and only 84
chunks embedded, `RssAnon` was **213 MiB** — inside the budget. The 1.5 GB was the runtime's
pools after 160 000 chunks of work, which is what the idle release is for.

### 2.5 Same-name disambiguation: no test, no side-by-side, 512 px, no zoom (1st §1.4, 2nd §2.2, 3rd §1.3 / F03) — **closed**

Three components and one test, all in `ui/`:

- **`ComparePane`.** Selecting exactly two rows (Ctrl+click, or Shift with an arrow key) turns the
  preview slot into a comparison: both names, then directory, size (rounded *and* in bytes),
  date (age *and* full timestamp), permissions, owner, tier and link target in the same order on
  both sides, the facts that differ highlighted and counted, both previews underneath. It
  computes nothing — the third pass was right that `brain.diff` is an episode feed and the daemon
  has no file diff — because seeing both was the ask.
- **`QuickLook`.** Space with an empty search field, or Ctrl+Space always, shows the cursor's
  file over the whole window at the screen's own pixel count up to the thumbnailer's 2048 px cap
  (D14). Two zoom states, fit and 1:1, toggled by click or `1` / `0`. Text files get eight times
  the pane's byte budget. Escape or Space closes. Typing while it is open is swallowed rather than
  sent to the search field — the first version of the test found that a `1` typed into the
  field changed the list under the picture.
- **`usePreview`.** The pane's loading logic, extracted so that the three places that show a
  preview share one implementation of the rule that text goes through `fs.read` (deny-list and
  audit apply) and pixels go to the killable helper. Three copies of a security rule would be
  three places for it to drift.
- **`disambiguation.spec.ts`.** Six tests: the rows differ visibly; the preview follows the
  cursor to the right file (asserted through the fixture rendering the two files at different
  sizes); selecting both shows the compare view with three differences marked; Quick Look asks for
  more pixels than the pane and leaves the search field untouched; Ctrl+Space works over a search;
  the column headers order the list.

One thing the test found on its first run, worth keeping: with sizes of 1.20 MB and 1.18 MB and
two dates in the same year, **the row read "1.2 MB" and "3 y" for both files.** The row alone
was never going to settle a close case, which is why the compare view prints bytes and the full
date, and why the fixture now uses sizes and ages that differ at the row's own precision.

Verified: `npm run test:ui` → **165 passed** (159 before, plus 6).

### 2.6 The benchmark corpus inside the live index (2nd §4.4, 3rd §2.4 / F06) — **closed in code; the live index clears at the next reconcile**

`.brainignore` — a marker file in a directory — is now honoured by all three walks: the first
index (`cortexd/src/indexer.rs`), the reconcile scan (`cortex-ingest/src/reconcile.rs`) and the
watcher (`cortex-ingest/src/watcher.rs`). `bench/corpus/generate.sh` writes it beside what it
generates, and it was written to `bench/corpus/data/` on this machine. Tests: the marked tree
stays out of a first walk, and — the live case — a marker added *after* a tree was indexed
removes its rows on the next reconcile without a rebuild.

Two honest notes. First, this was a documentation bug as well as an index bug: `09-INSTALL.md`
said `.gitignore and .brainignore are honoured` and neither was read by any walk. `.brainignore`
now is; `respect_gitignore` is documented as reserved and not yet acted on. Second, the running
daemon is the old binary, so its index still holds the corpus until the new one runs a
reconcile (hourly, or `cortex reconcile`).

### 2.7 A budget derived from its own measurement (2nd §4.2, 3rd §3.3 / F10) — **closed**

The contention gate is a fixed **45 ms** — 1.5 × the specified BM25 budget — and prints its
ratio to the same run's undisturbed P95 as information rather than gating on it (D104). Measured
this session: 25.45 ms against 45, at 1.17× the run's own baseline with 318 write batches
alongside. The specification table has the row.

### 2.8 Query embedding and rerank never measured (2nd §4.2, 3rd §3.3 / F11) — **query embedding closed; rerank stays unmeasured on this machine, and says why**

`bench-latency` looks in the daemon's model store — the directory `cortex model fetch` fills —
when the two environment variables are unset, and takes whichever runtime is installed with the
CPU as the device (the gate is about what a machine without a GPU pays). Query embedding is
**gated at 40 ms**, half the keystroke budget (D104). The first version of the fallback asked for
the CPU build of the runtime alone and reported "not measured" on the very machine the gate was
added for, which has only the GPU build; the GPU build runs on the CPU too, and the fallback now
takes it. Measured: **3.98 ms P95** on the CPU with eight threads — a tenth of its budget, and the first time this number has existed for the reference machine.

Reranking stays "not measured" here because no cross-encoder has been fetched on this machine;
the message now says so and names the command that would provide one.

### 2.9 MCP tool table drift ungated (2nd §3.2, 3rd §2.3 / F09) — **closed**

`NOT_A_TOOL` in `crates/cortex-mcp/src/tools.rs`: every RPC method the daemon serves is either a
row in `TOOLS` or an entry on that list with a reason a reader can check. A test walks
`method::ALL` and fails on a method that is neither, on one that is both, and on an exclusion
naming a method that no longer exists. Writing the list found two methods that are tools under
another spelling (`brain.search` is `search` with the caller's scope; `brain.explain` is
`search.explain`) — the kind of fact that was in nobody's head and is now in one place.
`07-AGENT-TOOLS.md` names the rule for whoever adds a tool.

## 5. What a reader should take from this

The reviews' most useful finding was not any one number; it was that the project trusted its
gates instead of running them, and the fix for that is the CI file, not the fourteen other
changes. Everything else here either makes a claim true that was written down as true (the
suites, the budget's configuration, the `.brainignore` sentence) or builds the one human-facing
thing three reviewers independently reached for and did not find. The two findings that remain
open remain open because they are measurements only the owner can take.
